# 需要決定的事

規格書沒寫清楚、會影響設計的地方。每一項都已先採用「目前預設」繼續開發，等你決定後再調整。

## 1. 文字生成模型（潤飾、腳本）
- **問題**：規格書寫「文字生成的模型另定」。
- **選項**：Claude（Anthropic API）、GPT（OpenAI）、Gemini；或 Higgsfield 若有提供文字模型。
- **建議**：Claude Sonnet 系列，中文寫作與 JSON 結構化輸出穩定；需要 API 金鑰（放 `.env`，系統不會讀出或印出）。
- **目前預設**：假實作（`AI_PROVIDER=fake`），結果固定、不花錢。

## 2. Higgsfield 存取方式與模型名稱
- **問題**：需要 Higgsfield 的 API 金鑰、API 文件（端點、非同步任務查詢方式），以及圖片模型與影片模型（Seedance 2.0）的正式名稱與價格。
- **選項**：(a) 提供 API 金鑰與文件，由系統直接呼叫；(b) 若沒有公開 API，只能手動在 Higgsfield 網站生成後上傳結果。
- **建議**：(a)。轉接層已預留介面，只要補上 provider。
- **目前預設**：假實作；`prompt-studio/prompts/` 中圖片、影片節點的 `target.model` 維持空白（使用預設模型），畫面比例已改為 16:9。`shot-video.json` 已放入 `seedance-2.0` 與 `kling-2.1` 兩套模型專用寫法（`modelRules`），確定模型名稱後把 `target.model` 填成對應的名稱即可套用。

## 3. 價格表、每支影片上限與單筆門檻
- **問題**：成本控管需要各服務的單價，規格書沒有數字。
- **目前預設**（`app/src/cost/prices.js`，可改）：文字 US$0.01／次、圖片 US$0.04／張、影片 US$0.10／秒、語音 US$0.01／次；每支影片上限 US$20、單筆門檻 US$2。
- **建議**：拿到 Higgsfield 實際價格後更新價格表；上限可在系列設定中調整。

## 4. 去識別偵測器
- **問題**：要偵測信眾、路人臉孔與車牌，但「神像臉部不得被遮蔽」，一般人臉偵測器分不出神像與真人。
- **選項**：(a) 本機 OpenCV Haar（免費，人臉尚可，車牌只對部分格式有效）；(b) 本機深度學習模型（如 YuNet、YOLO 車牌，需下載模型檔，免費）；(c) 雲端服務（付費，且照片未去識別前就送出，違反規格）。
- **建議**：(b)，並保留人工確認。
- **目前預設**：有 `python3` + `cv2` 時用 OpenCV，否則用假偵測器；偵測結果會顯示給使用者，使用者可以取消誤判的區塊（例如神像），也可以手動加框。

## 5. 背景音樂來源
- **問題**：規格要求全片背景音樂，但沒有說音樂從哪裡來（授權問題）。
- **選項**：(a) 使用者自己上傳有授權的音樂；(b) 免版稅音樂庫；(c) AI 音樂生成服務（付費）。
- **建議**：(a)，最單純且授權清楚。
- **目前預設**：內建 3 首本機合成的佔位音樂，並可上傳自己的音樂檔。

## 6. 台詞語音
- **問題**：「模型原生語音並對口型，或語音合成」。原生語音取決於影片模型；語音合成的服務未定。
- **目前預設**：兩種模式都做；語音合成用假實作（本機產生的提示音）。真實的語音合成服務待定。

## 7. 影片秒數與分鏡格數
- **問題**：規格寫 8～12 格、每格 2～4 秒，但 15 秒的影片無法同時滿足（8 格 × 2 秒 = 16 秒）。
- **目前預設**：秒數選項 15／20／30 秒（介面設計稿）與自訂（5～30 秒）；格數 = 依秒數每格約 3 秒，限制在 4～12 格之間；確認條件是各格秒數加總與系列秒數相差不超過 0.5 秒。

## 8. 輸出解析度
- **問題**：規格寫 1920×1080，但參考影片是 1280×720。
- **目前預設**：1920×1080、24 fps。

## 9. 短期網址有效時間
- **目前預設**：1 小時；伺服器重啟後重新產生簽章金鑰，舊網址失效。

## 10. 資料儲存
- **目前預設**：本機 JSON 檔（`app/data/`），適合單人使用。若之後要多人共用或資料量變大，建議換 SQLite（只需替換儲存層）。
