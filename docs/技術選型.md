# 技術選型

規格書沒有指定技術堆疊，以下是本機個人使用的選擇與理由。

| 層 | 選擇 | 理由 |
| --- | --- | --- |
| 執行環境 | Node.js 22（最低 18），CommonJS | 與既有的 `prompt-studio/` 相同，可以直接 `require` 它的 `lib/prompt.js`，不必維護兩套 prompt 組裝邏輯 |
| HTTP 伺服器 | `node:http` 自寫小路由，不用框架 | 個人本機使用、API 數量有限；與 prompt-studio 一致，執行時零套件 |
| 資料儲存 | `app/data/` 下的 JSON 檔（原子寫入、寫入排隊） | 單人單機，資料量小（每支影片數十筆紀錄）；不需安裝資料庫，備份就是複製資料夾。若之後要多人使用，再換 SQLite（儲存層只有一個模組） |
| 媒體檔 | `app/data/media/`（可公開，經短期網址）與 `app/data/private/`（原圖，不提供任何網址） | 符合「原圖保持私有」「照片與成品以短期網址存取」 |
| 圖片遮蔽、影片合成 | 本機 `ffmpeg`（已安裝，含 libx264、libass、drawtext） | 免費、本機執行；裁切模糊、串接、燒錄字幕、混音都能用同一工具完成 |
| 人臉與車牌偵測 | 介面 + 兩種實作：假實作（測試用）、本機 OpenCV（`python3` + `cv2`，Haar 分類器） | 免費、不送出網路；偵測器只是一層，之後可換更準的模型（見 BLOCKED.md） |
| 前端 | 單頁 HTML + 原生 JavaScript + CSS，由同一個 Node 伺服器提供 | 不需要建置工具；畫面依 `介面設計/預覽/` 實作 |
| 單元與整合測試 | `node:test` + `node:assert` | 內建、零安裝，與 prompt-studio 一致 |
| 端對端測試 | `@playwright/test`（開發相依，免費開源） | 能操作真實瀏覽器走完 6 步並驗證下載 |
| BDD 情境 | `features/*.feature`（Gherkin 繁中）+ `scripts/check-features.js` 對照測試名稱 | 不另外引入 Cucumber；情境標題必須出現在某個測試名稱中，閘門會檢查 |
| 外部 AI 服務 | 轉接層（provider）介面：文字、圖片、影片、語音、音樂；預設為假實作 | 測試與開發都不花錢；換成真實服務時只換 provider 設定（見 BDD與TDD開發方法.md） |

## 執行時需要的本機工具

- Node.js 18 以上
- `ffmpeg` / `ffprobe`（Homebrew：`brew install ffmpeg`）
- 選用：`python3` + `opencv-python`（真實人臉偵測；沒有時使用假偵測器並在畫面上提示）
