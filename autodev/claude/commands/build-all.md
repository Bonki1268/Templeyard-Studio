你要以 BDD + TDD 把「廟埕影室」開發完成，中途不要停下來問我，規則見 `CLAUDE.md`。

## 第 0 階段：規劃（`docs/PROGRESS.md` 不存在時才做）
1. 完整閱讀 `規格書/廟埕影室 系統規格書.md` 與 `prompt-studio/README.md`。
2. 規格書沒指定技術堆疊時，選一套適合個人本機使用的堆疊，理由寫進文件。
3. 寫 `docs/BDD與TDD開發方法.md`：
   - 測試分層（單元、整合、端對端）各測什麼、用什麼工具。
   - 外部 AI 服務的假實作設計：結果固定、不花錢，之後換成真實服務時只換一層。
   - BDD 情境怎麼對應到測試檔，紅燈 → 綠燈 → 重構的實際操作。
4. 把系統拆成依序的開發步驟，每步要小到一次可以完成，寫進 `docs/PROGRESS.md`：
   - 每一行：`- [ ] 步驟 N：名稱｜範圍｜對應規格書章節｜完成條件`
   - 第 1 步是專案骨架與 `scripts/gate.sh`。
   - 最後一步是端對端測試：用假實作完整走完 6 個步驟並下載成品。
5. 把規格書沒寫清楚、會影響設計的地方寫進 `docs/BLOCKED.md`，先採用最合理的預設。
6. commit 並 push：「步驟 0：開發計畫」。

## 第 1 階段：逐步開發（重複到全部完成）
對 `docs/PROGRESS.md` 中第一個 `- [ ]` 的步驟：
1. 寫或更新該步驟的 `features/*.feature`。
2. 紅燈：寫測試並執行，確認失敗的原因是功能還沒做。
3. 綠燈：寫最少的程式讓測試通過。
4. 重構。
5. 執行 `bash scripts/gate.sh`，沒過就修到過。
6. commit 並 push，打勾並記下 commit 雜湊。
7. 立刻接著做下一步。

全部步驟都是 `[x]` 或 `[~]` 後，在 `docs/PROGRESS.md` 最後寫總結：完成了什麼、怎麼啟動系統、`docs/BLOCKED.md` 裡有哪些需要我決定的事。
